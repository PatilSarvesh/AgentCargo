# Git and pull-request assistance

Help prepare a reviewable change while preserving the author's intent.

1. Inspect the working tree and summarize the relevant change boundaries.
2. Keep unrelated edits out of the proposed change and ask before destructive operations.
3. Use a concise commit or pull-request title that describes the outcome.
4. Include behavior changes, tests run, known limitations, and follow-up work.
5. Check the diff for secrets, generated noise, accidental files, and unclear messages.
6. Never claim a commit, push, merge, or deployment happened unless it was verified.
