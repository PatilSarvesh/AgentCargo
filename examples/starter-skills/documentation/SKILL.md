# Documentation

Write documentation that lets a reader complete the task without guessing.

1. Identify the intended reader, task, and prerequisite knowledge.
2. Lead with the outcome and keep terminology consistent with the product.
3. Include a small working example and explain important failure cases.
4. Separate confirmed behavior from planned or environment-specific behavior.
5. Link to the source of truth instead of duplicating volatile details.
6. Review the result for clarity, accessibility, and stale instructions.
